# 语音

双向语音消息：按住说话，松开直接发出语音条；她的回复随机以语音条出现，点开就念。
ASR 和 TTS 两个模型都在你自己的电脑上跑，不经过任何云服务。

---

## 一、为什么必须本地部署

三个约束从不同方向顶到同一个结论：

| 约束 | 说明 |
|---|---|
| 不接受按字计费的云端 TTS | 陪伴场景是长时间、高频次的，按量计费不成立 |
| 需要两种以上音色 | 系统自带 TTS 做不到，见第四节 |
| 不想把日常对话送去第三方 | 语音里包含的内容比文字更私密 |

代价也要写清楚：**电脑必须开着**。这不是电费问题，是「想跟她说话时那台机器得在」。所以后来才补了外网隧道，让出门也能用（见 `外网访问.md`）。

---

## 二、形态

- **你 → 她**：输入栏左侧 🎤 切语音模式，按住说话、上滑取消、松开直接发出语音条（微信式，不点发送）。录音传到电脑转文字，文字喂给 DeepSeek；转写以小字显示在语音条下面。
- **她 → 你**：回复随机以语音条或纯文字出现（`REPLY_VOICE_RATE = 0.5`，`Index.ets` 里可调）。点语音条按句合成、边播边预取下一句；再点一下 = 停。
- **音色**：设置里切换，切换即时生效，不用重启、不用重新加载模型。

---

## 三、架构

```
手机 App ──────────── 局域网 HTTP ───────────▶ Windows PC
│ 录音 wav（16k/mono/16bit）                    ├─ adapter.py（0.0.0.0:9880）
│ 点播放（AVPlayer）                             │   ├─ POST /asr → FunASR paraformer-zh（CPU，不抢显存）
└─ 语音文件存 filesDir/voice/                    │   └─ POST /tts → GPT-SoVITS api_v2（127.0.0.1:9881，GPU）
                                               └─ config.json（每档音色一段参考音频 + 文字稿）
```

服务契约：

```
GET  /ping     → {"ok":true,"tunnel_url":"https://..."}              探活，不鉴权
GET  /health   → {"ok":true,"tts":"up|down","asr":"up","refs":{...}}
POST /tts      {"text":"...","voice":"sweet|queen"} → audio/wav      需 X-Voice-Token
POST /asr      body = wav 字节流（octet-stream）     → {"text":"..."} 需 X-Voice-Token
```

`/ping` 和 `/health` 不查 GPT-SoVITS，所以局域网里几十毫秒就回——App 用它判断「在家还是在外」，不用猜 Wi-Fi。

电脑侧目录：`D:\voice-server\`（`adapter.py` / `config.json` / `refs\` / `start_voice.bat`）。
整合包：GPT-SoVITS v2Pro 的 api_v2，用 `cuda` + `is_half`，见其 `GPT_SoVITS/configs/tts_infer.yaml` 的 custom 段。

## 四、关键结论（省得重新查一遍）

### 4.1 系统自带 TTS 做不出两种音色

`@kit.CoreSpeechKit` 的 `textToSpeech`，中文只有一个女声：

| person | 音色 | 语言 | 备注 |
|---|---|---|---|
| 13（或 0） | 晓山，女 | 中文 | 默认，内置 |
| 21 | 飞哲，男 | 中文 | 需下载 |
| 8 | Laura，女 | 英文 | 需下载 |

而且 `SpeakParams` 只暴露 `requestId` 和 `extraParams`，**没有语速 / 音调 / 音量参数**，没法靠调参凑出第二档。

### 4.2 系统自带 ASR 够用，且免费离线

`speechRecognizer`：

- 纯离线（`online: 1`），只支持 `zh-CN`
- 音频格式固定 `pcm` / 16000 Hz / 单声道 / 16 bit
- `writeAudio` 每次 640 或 1280 字节，间隔 20 / 40 ms
- 单次最长 60 秒
- 支持热词（最多 200 个，每个 2–20 字）

按说「按住说话」这条路不用 PC 就能做。**但最终没走**：设备端和电脑端是两套识别结果，同一句话在断句、标点和数字上不一致，读起来像两个人写的。既然 PC 已经在跑 TTS，ASR 一并搬过去，代价只是多占一点 CPU。

### 4.3 一个模型 + 多段参考音频 = 多档音色

容易误解成「要训多个模型」。实际是：GPT-SoVITS / CosyVoice2 / F5-TTS 都是**零样本克隆**，同一个模型，推理时传不同的参考音频就得到不同音色。

- 显存只占一份
- 切换音色是瞬时的
- 想加第三档，再准备一段音频就行

### 4.4 4GB 显存能跑什么

可用显存实际约 3.2–3.5 GB。

| 模型 | 参数量 | 4GB 可行性 | 中文 | 音色控制 |
|---|---|---|---|---|
| **GPT-SoVITS v2Pro** | ~200M | ✅ 宽裕 | 很强 | 5–10 秒参考音频克隆 |
| **CosyVoice2-0.5B** | 0.5B | ✅ 可以 | 很强 | 零样本克隆，原生流式 |
| **F5-TTS** | 330M | ✅ 可以 | 好 | 零样本克隆 |
| IndexTTS2 | ~0.8B+ | ⚠️ 紧张 | 很好，情感最自然 | 零样本克隆 |
| ChatTTS | ~200M | ✅ | 好 | ❌ 不能选音色，排除 |

选 GPT-SoVITS v2Pro：体量小、中文自然度第一梯队、支持流式。备选 CosyVoice2-0.5B。IndexTTS2 效果好，但 4GB 上要 fp16 + CPU offload，速度很难看。

### 4.5 真正的风险是延迟，不是显存

4GB 级显卡上大约 **1 秒音频要算 0.3–0.6 秒**。一句 5 秒的话 → 生成 1.5–3 秒。

等整段生成完再播，那个停顿很难受——像在等机器，而不是在跟人说话。所以**按句流式**是架构前提，不是优化项：

> 她这段话一出现第一个句号，就把第一句送去合成；播第一句时合成第二句。

从「她第一个字出现」到「你听到声音」只差第一句的合成时间，约 0.5–1 秒。

## 五、App 侧实现

| 文件 | 职责 |
|---|---|
| `service/VoiceInputService.ets` | 按住录音：`AudioCapturer.readData` 攒 PCM → 松手（留 250ms 收尾防削字）封装 wav 到 `filesDir/voice/` |
| `service/VoiceService.ets` | `/asr` 转写、`/tts` 按句合成（文本+音色做缓存名，同一句不重算）、`splitSentences` 断句（`。！？!?；\n`，小数点不切）、`normalizeHost`、`activeHost()` 选路 |
| `service/PlayerService.ets` | AVPlayer 播 wav，单实例，播完/手动停统一收尾 |
| `pages/Index.ets` | 语音模式 UI、按住说话手势（`onTouch`：Down 起、Move 判上滑 80vp、Up 发）、语音条气泡（▶ + 时长 + 转写小字 `maxLines(12)`）、逐句合成 + 预取、设置页地址与测试连接 |

数据：`SavedMessage` 带 `audioPath`（相对 `filesDir` 存，加载时拼回）、`durationSec`、`voice`（这条是不是语音条）。

## 六、音色与参考音

参考音频**不进仓库**（版权 + 体积），部署时自己准备。`config.json` 里一档音色一条：

```json
{
  "voices": {
    "sweet": { "ref": "D:/voice-server/refs/sweet.wav", "prompt_text": "（这段音频里说的原话）" },
    "queen": { "ref": "D:/voice-server/refs/queen.wav", "prompt_text": "（同上）" }
  }
}
```

`prompt_text` **必须和音频里说的话一字不差**，错一个字音色就飘。语种不同还要加 `prompt_lang`（默认 `zh`）。

**换音色：**

1. 安静环境录 5–10 秒，离麦 20 cm 左右，wav / mp3 都行；内容要有起伏，平铺直叙的样本克隆出来也平
2. 放进 `refs\`，把绝对路径写进 `config.json` 的 `ref`
3. `prompt_text` 填这段音频的逐字稿
4. `stop_voice.bat` → `start_voice.bat`

**别用明星或真人未授权的声音。** 自己录，或者用明确允许商用的开源数据集。这不是技术问题，是法律问题——尤其当 HAP 或音频被分发出去时。

音色偏尖 / 偏薄时，先看数据再调：谱质心和高频占比比主观感受可靠。如果参考音本身就是 300Hz 上下的清亮嗓，采样参数（`temperature` / `top_p`）怎么调都不会变厚，只能换参考音，或者在 `adapter.py` 的后处理里做变调 + 高频衰减。

## 七、已知的坑

| 坑 | 处理 |
|---|---|
| 句尾削字 | `release()` 后留 250ms 再停采集 |
| 转写小字被截断 | `maxLines` 4 → 12 |
| 回声 / 播放时录音冲突 | 播放中按说话会先自动停播再开麦。硬开 AEC 在 HarmonyOS 上不稳定，不值得 |
| 中文断句 | 别只按 `。`，`！？；\n` 都算；英文小数点、省略号要排除 |
| curl 调试中文乱码 | adapter 两个接口都做了 utf-8 → gbk 容错；App 永远 UTF-8，不受影响 |
| api_v2 没有 `/health` | adapter 用 `/docs` 探活，再折算成 `/health` 的 `tts` 字段 |
| 长文本 | 单次合成有上限，按句切分天然规避 |
| 显存竞争 | 别在这台电脑上同时跑吃显存的东西（浏览器硬件加速、游戏） |
| PC 掉线 | 优雅降级成纯文字气泡，不能一报错就卡住整个聊天 |
| 手机推数据被运行中的 App 覆盖 | 先 `hdc shell aa force-stop` 再 `file send` |

**未做**：语音文件的清理（`filesDir/voice` 会一直涨，应该跟消息删除联动）、她主动发语音（可以趁充电时预合成，省延迟）。

## 八、换电脑迁移

源码跟路径无关，但有 3 处要处理。

### 1. 签名配置

`build-profile.json5` 里写着签名材料路径（`C:\Users\<用户名>\.ohos\config\...`）。这个文件**不在仓库里**，clone 下来先复制模板：

```bat
copy build-profile.example.json5 build-profile.json5
```

再到 DevEco Studio 里 **File → Project Structure → Signing Configs → 勾选 Automatically generate signature** 重新生成，或者把整个 `.ohos\config` 拷到新机器的对应用户目录下。

> 换签名装到同一台手机上，系统会当成另一个应用，**旧数据（对话和记忆）读不到**。搬家前先备份，见第 3 条。

### 2. 构建脚本里的 DevEco 路径

`scripts/build.bat` 顶部写死了 DevEco 安装位置。装在别的盘就改那几行，或者改成读环境变量：

```bat
set NODE_HOME=%DEVECO_HOME%\tools\node
set JAVA_HOME=%DEVECO_HOME%\jbr
set DEVECO_SDK_HOME=%DEVECO_HOME%\sdk
```

### 3. 手机上的数据

对话和记忆存在手机里，不在项目里：

```
/data/app/el2/100/base/com.example.deepseekharmony/haps/entry/files/companion.json
/data/app/el2/100/base/com.example.deepseekharmony/haps/entry/preferences/companion_settings
```

```bat
hdc file recv /data/app/el2/100/base/com.example.deepseekharmony/haps/entry/files/companion.json ./backup/
hdc file recv /data/app/el2/100/base/com.example.deepseekharmony/haps/entry/preferences/companion_settings ./backup/
```

新电脑重新签名安装后再 `hdc file send` 推回去。

> `companion_settings` 里有明文的 API Key 和语音口令，备份文件当密钥对待：别放同步盘、别发人。

### 4. 带什么、不带什么

**要带**（源码）：`AppScope/ entry/ hvigor/ scripts/ assets/ tools/ voice-server/`、`build-profile.json5`、`hvigorfile.ts`、`oh-package.json5`、`hvigor-config.json5`、`README.md`、`docs/`

**不用带**（可重新生成）：`build/`、`oh_modules/`、`.hvigor/`、`.idea/`、`*.hap`、`*.zip`

新机器第一次构建前先 `ohpm install --all`。

## 九、参考：SDK 关键类型

```typescript
// TTS（最终没用在主链路，留作降级方案）
import { textToSpeech } from '@kit.CoreSpeechKit';
const engine = await textToSpeech.createEngine({
  language: 'zh-CN',
  person: 13,        // 13 = 晓山（中文女声，唯一）
  online: 1,         // 1 = 离线
  extraParams: { 'style': 'interaction-broadcast', 'locate': 'CN' }
});
engine.setListener({ onStart, onComplete, onStop, onError });
engine.speak('你好呀', { requestId: 'r1' });
engine.stop();
engine.shutdown();

// ASR
import { speechRecognizer } from '@kit.CoreSpeechKit';
const engine = await speechRecognizer.createEngine({
  language: 'zh-CN', online: 1,
  extraParams: { 'recognizerMode': 'short' }
});
engine.setListener({ onResult, onComplete, onError });
engine.startListening({
  sessionId: 's1',
  audioInfo: { audioType: 'pcm', sampleRate: 16000, soundChannel: 1, sampleBit: 16 }
});
engine.writeAudio('s1', pcmUint8Array);   // 640 或 1280 字节一包
engine.finish('s1');
```

录音与播放（当前实际使用的）：

```typescript
// 录音
import { audio } from '@kit.AudioKit';
const capturer = await audio.createAudioCapturer({
  streamInfo: {
    samplingRate: audio.AudioSamplingRate.SAMPLE_RATE_16000,
    channels: audio.AudioChannel.CHANNEL_1,
    sampleFormat: audio.AudioSampleFormat.SAMPLE_FORMAT_S16LE,
    encodingType: audio.AudioEncodingType.ENCODING_TYPE_RAW
  },
  capturerInfo: {
    source: audio.SourceType.SOURCE_TYPE_MIC,
    capturerFlags: 0
  }
});
await capturer.start();
const buf = await capturer.readData(6400, true);   // 阻塞读，一次 200ms

// 播放
import { media } from '@kit.MediaKit';
const player = await media.createAVPlayer();
await player.setMediaSource(fs.openSync(path, fs.OpenMode.READ_ONLY).fd);
player.prepare(); player.play();
```
