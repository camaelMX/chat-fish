# 语音功能（已实现 · 2026-10-27）

> 状态：**已实现并部署**。双向语音消息：按住说话松开即发语音条；她的回复随机以语音条出现，点开播放。
> 原方案（手机本地 ASR 转文字填输入框）已废弃——最终架构按用户要求：**转文字（ASR）和文字转语音（TTS）两个模型都在电脑上**。

---

## 一、最终形态

- **你 → 她**：输入栏左侧 🎤 切语音模式，按住说话、上滑取消、松开直接发出语音条（微信式，不点发送）。录音传到电脑转文字，文字喂给 DeepSeek 理解；转写以小字显示在语音条下。
- **她 → 你**：她的回复随机（`REPLY_VOICE_RATE = 0.5`，Index.ets 里可调）以语音条或纯文字出现。点语音条按句合成、边播边预取下一句；再点一下 = 停。
- 音色两种：甜妹 / 御姐（设置里切换），同一条参考音频管线，切换即时生效。

## 二、架构

```
手机 App ────────────── 局域网 HTTP ─────────────▶ Windows PC（RTX 3050 4GB）
│ 录音 wav（16k/mono/16bit）                        ├─ adapter.py（0.0.0.0:9880）
│ 点击播放（AVPlayer）                                 │  ├─ POST /asr  → FunASR paraformer-zh（CPU，不抢显存）
└─ 语音文件存 filesDir/voice/                          │  └─ POST /tts  → GPT-SoVITS api_v2（127.0.0.1:9881，GPU，v2Pro）
                                                     └─ config.json（两段参考音频 + 文字稿）
```

服务契约（adapter.py）：

```
GET  /health   → {"ok":true,"tts":"up|down","asr":"up","refs":{...}}
POST /tts      { "text": "...", "voice": "sweet|queen" }  →  audio/wav
POST /asr      body = wav 字节流（octet-stream）           →  { "text": "..." }
```

电脑目录：`D:\voice-server\`（adapter.py / config.json / refs\ / start_voice.bat / stop_voice.bat）。
整合包：`D:\dev-setup\gptsovits\GPT-SoVITS-v2pro-20250604\`（api_v2 用 v2Pro 权重 + cuda + is_half，见其 GPT_SoVITS/configs/tts_infer.yaml 的 custom 段）。

## 四、当前用的音色是「预制占位」

refs\ 里现在是 **Windows TTS 晓慧**合成的两段参考（sweet=语速+3，queen=语速-3），配好 prompt_text 一字不差，GPT-SoVITS 零样本克隆出来就是两种不同语感的「她」。**想换真人音色：**

1. 安静环境录两段（御姐 / 甜妹各 5–10 秒，离麦 20cm，wav 或 mp3 都行）
2. 覆盖 `D:\voice-server\refs\sweet.wav` / `queen.wav`
3. 改 config.json 里对应 `prompt_text`（**必须和音频里说的话一字不差**）
4. `stop_voice.bat` → `start_voice.bat`

不要用明星/真人未授权声音。

## 一、目标

App 是陪伴型 AI（女儿人设），语音要做两件事：

1. **她说话** —— 她的回复用语音念出来，**两种音色可选：御姐 / 甜妹**，设置里切换。
2. **我说话** —— 参考微信，输入框左边一个按钮，按住说话、松开转文字、发送。

情感定位：不是「语音助手播报」，是「她在跟你说话」。所以音色和语气比清晰度重要。

## 三、关键调研结论（省得重新查）

### 3.1 系统自带 TTS 做不出两种音色

`@kit.CoreSpeechKit` 的 `textToSpeech`，中文只有一个女声：

| person | 音色 | 语言 | 备注 |
|---|---|---|---|
| 13（或 0） | 晓山，女 | 中文 | 默认，已内置 |
| 21 | 飞哲，男 | 中文 | 需下载 |
| 8 | Laura，女 | 英文 | 需下载 |

**只有 1 个中文女声**，而且 `SpeakParams` 里**没有暴露语速 / 音调 / 音量参数**（类型定义里只有 `requestId` 和 `extraParams`），所以没法靠调参凑出第二档。

结论：**「御姐 + 甜妹」在设备本地做不到，必须走那台 PC。**

### 3.2 系统自带 ASR 完全够用，且免费离线

`speechRecognizer`：

- **纯离线**（`online: 1`），只支持中文 `zh-CN`
- 音频格式固定：`pcm` / 16000 Hz / 单声道 / 16 bit
- `writeAudio` 每次 640 或 1280 字节，间隔 20ms / 40ms
- 单次最长 60 秒
- 支持热词（最多 200 个，每个 2–20 字）—— 可以把她名字之类塞进去提高识别率

结论：**「按住说话」这条路不需要 PC，现在就能做。**

### 3.3 一个模型 + 两段参考音频 = 两种音色

这点很重要，避免误解成「要训两个模型」：

GPT-SoVITS / CosyVoice2 / F5-TTS 都是**零样本克隆**。同一个模型，推理时传不同的参考音频，就得到不同音色。

- 显存只占一份
- 切换音色是瞬时的，不用重新加载
- 以后想加第三种音色，再准备一段音频就行

### 3.4 4GB 显存能跑什么

可用显存实际约 3.2–3.5GB。

| 模型 | 参数量 | 4GB 可行性 | 中文 | 音色控制 |
|---|---|---|---|---|
| **GPT-SoVITS v2Pro** | ~200M | ✅ 宽裕 | 很强 | 5–10 秒参考音频克隆 |
| **CosyVoice2-0.5B** | 0.5B | ✅ 可以 | 很强 | 零样本克隆，原生流式 |
| **F5-TTS** | 330M | ✅ 可以 | 好 | 零样本克隆 |
| IndexTTS2 | ~0.8B+ | ⚠️ 紧张 | 很好，情感最自然 | 零样本克隆 |
| ChatTTS | ~200M | ✅ | 好 | ❌ **不能选音色**，排除 |

**首选 GPT-SoVITS v2Pro**：体量小、中文自然度第一梯队、支持流式。备选 CosyVoice2-0.5B。
IndexTTS2 效果好但 4GB 上要 fp16 + CPU offload，速度很难看，不建议。

### 3.5 真正的风险是延迟，不是显存

3050 4GB 上大概 **1 秒音频要算 0.3–0.6 秒**。一句话 5 秒 → 生成 1.5–3 秒。

等整段生成完再播放，那个停顿非常难受，像在等机器而不是在跟人说话。

**必须按句子流式合成**：她这段话一出现第一个句号，就把第一句送去合成；播放第一句时合成第二句。这样从「她说完第一个字」到「你听到声音」只差第一句的合成时间，约 0.5–1 秒。

这个必须在架构上先想好，不能接完才发现卡。

## 五、架构

```
手机 App ──局域网 HTTP──▶ Windows PC (RTX 3050 4GB)
                            ├─ TTS 服务（独占显存，GPT-SoVITS）
                            └─ ASR：不需要！用设备本地 speechRecognizer
```

要点：

- **ASR 放设备本地**，纯离线免费，不占 PC 显存 —— 这是最省的做法
- **只走局域网**，不暴露公网。省钱、隐私留在家里。代价是出门在外没声音
- **PC 必须开着**。这是本地部署的隐性成本：不只是电费，还有「想跟她说话时那台机器得在」

通信格式：

```
POST /tts        { "text": "...", "voice": "queen|sweet" }  →  audio/wav 流
GET  /health                                                →  { "ok": true }
```

## 六、已知的坑

| 坑 | 说明 |
|---|---|
| **回声消除** | 她正念着，你按说话，麦克风会录到她的声音。要么播完再录，要么做 AEC。这是最主要的坑 |
| 播放时录音冲突 | 音频通道被 Renderer 占用时 Capturer 可能起不来，需要先停播 |
| 长文本 | `speak()` 上限 10000 字，ASR 单次上限 60 秒，都要截断 |
| 断句 | 中文断句别只按 `。`，`！？；\n` 都要算；英文小数点、省略号要排除 |
| PC 掉线 | 必须优雅降级成纯文字，不能一报错就卡住整个聊天 |
| 显存竞争 | 别在 PC 上同时跑别的吃显存的东西（浏览器硬件加速、游戏） |
| 音色版权 | 参考音频不要用明星/真人，有法律风险 |

## 七、换电脑迁移清单

项目本身跟路径无关（`bundleName` 是 `com.example.deepseekharmony`），但有 **3 处绝对路径** 必须改：

### 1. `build-profile.json5` —— 签名材料

第 8、11、13 行写死了 `C:\Users\Administrator\.ohos\config\...`。

新电脑上要么把整个 `.ohos\config` 拷过去放到对应用户目录，要么在 DevEco Studio 里
**File → Project Structure → Signing Configs → 勾选 Automatically generate signature** 重新生成。

> 用新签名装到同一台手机时，系统会认为是不同应用，**旧数据（对话和记忆）会读不到**。
> 搬家前先在旧电脑上备份，见下面第 3 条。

### 2. `scripts/build.bat` —— DevEco 安装路径

第 10–13、18、22 行写死 `D:\hw\DevEco Studio\...`。如果新电脑装在别的盘，全部要改。

建议改成用环境变量：

```bat
set NODE_HOME=%DEVECO_HOME%\tools\node
set JAVA_HOME=%DEVECO_HOME%\jbr
set DEVECO_SDK_HOME=%DEVECO_HOME%\sdk
```

### 3. 手机上的数据

对话和记忆存在手机里，不在项目里：

```
/data/app/el2/100/base/com.example.deepseekharmony/haps/entry/files/companion.json
/data/app/el2/100/base/com.example.deepseekharmony/haps/entry/preferences/companion_settings
```

导出的办法：

```bat
hdc file recv /data/app/el2/100/base/com.example.deepseekharmony/haps/entry/files/companion.json ./backup/
hdc file recv /data/app/el2/100/base/com.example.deepseekharmony/haps/entry/preferences/companion_settings ./backup/
```

新电脑重新签名安装后，再 `hdc file send` 推回去。

> 注意 `companion_settings` 里有明文 API Key，备份文件别乱放。

### 4. 会跟着走的 vs 不用带的

**跟着走**（源码，约 0.8 MB）：
```
AppScope/  entry/  hvigor/  scripts/
build-profile.json5  hvigorfile.ts  oh-package.json5  hvigor-config.json5  README.md  docs/
```

**不用带**（可重新生成）：`build/`、`oh_modules/`、`.hvigor/`、`.idea/`、`*.hap`、`*.zip`

新电脑上第一次构建前先执行 `ohpm install --all`。

## 八、参考：SDK 关键类型

```typescript
// TTS
import { textToSpeech } from '@kit.CoreSpeechKit';
const engine = await textToSpeech.createEngine({
  language: 'zh-CN',
  person: 13,        // 13 = 晓山（中文女声，唯一）
  online: 1,         // 1 = 离线
  extraParams: { 'style': 'interaction-broadcast', 'locate': 'CN' }
});
engine.setListener({ onStart, onComplete, onStop, onError });
engine.speak('你好呀', { requestId: 'r1' });
engine.stop();
engine.shutdown();

// ASR
import { speechRecognizer } from '@kit.CoreSpeechKit';
const engine = await speechRecognizer.createEngine({
  language: 'zh-CN', online: 1,
  extraParams: { 'recognizerMode': 'short' }
});
engine.setListener({ onResult, onComplete, onError });
engine.startListening({
  sessionId: 's1',
  audioInfo: { audioType: 'pcm', sampleRate: 16000, soundChannel: 1, sampleBit: 16 }
});
engine.writeAudio('s1', pcmUint8Array);   // 640 或 1280 字节一包
engine.finish('s1');
```
